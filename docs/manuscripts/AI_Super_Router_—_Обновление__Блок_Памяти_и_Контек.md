# AI Super Router — Обновление: Блок Памяти и Контекста

## Что сделано (День 1)

### Проблема
Роутер переключался между провайдерами и моделями, но **терял контекст** при каждом вызове. Каждый запрос был «с чистого листа» — система не помнила ни предыдущие сообщения, ни факты о пользователе.

### Решение: Модуль `core/memory.py`

Полноценная система памяти с тремя уровнями:

| Уровень | Что хранит | Время жизни |
|---------|-----------|-------------|
| **Сессионная** | История сообщений текущего диалога | До закрытия сессии |
| **Долговременная** | Факты, сущности, предпочтения | Навсегда (файлы JSON) |
| **Handoff** | Контекст для передачи при смене провайдера | До использования |

### Ключевые возможности

1. **Сохранение контекста между сменами провайдера** — если Groq упал, система переключается на Cerebras, но передаёт сжатый контекст предыдущего диалога
2. **Автоматическое извлечение фактов** — из сообщений пользователя система запоминает имя, город, навыки, предпочтения
3. **Multi-turn диалоги** — полная история передаётся провайдеру (с учётом лимита контекстного окна)
4. **Сущности** — система ведёт карточки людей, проектов, инструментов с которыми взаимодействует пользователь
5. **Парадигмальная линза** — возможность переключать «мировоззрение» системы (кибернетика, И Цзин и т.д.)
6. **Персистентность** — всё сохраняется в JSON-файлах, переживает перезапуск

### Обновлённые файлы

- `core/memory.py` — **новый** (основной модуль памяти, ~900 строк)
- `core/client.py` — **переписан** (поддержка multi-turn messages, handoff-контекст)
- `main.py` — **обновлён** (интеграция памяти в chat и serve команды)
- `config/providers.yaml` — **дополнен** (секция memory_config)
- `core/__init__.py` — **обновлён** (экспорт Memory)

### Тесты

Все 5 интеграционных тестов пройдены:
- ✅ Простой prompt → messages
- ✅ Multi-turn history
- ✅ Handoff context injection

- ✅ Memory → full messages pipeline
