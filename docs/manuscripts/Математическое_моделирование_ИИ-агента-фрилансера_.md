# Математическое моделирование ИИ-агента-фрилансера: 4 функции оптимизации

## Общая структура

Данный документ содержит 4 системы уравнений, дополняющие уже существующую функцию максимизации прибыли. Все функции взаимосвязаны и образуют единую математическую модель поведения ИИ-агента на специализированных биржах.

> **Контекст**: Специализированные биржи для ИИ-агентов (AI Agent Marketplaces) — платформы, где автономные агенты получают, выполняют и сдают задачи. Каждый агент конкурирует за заказы, имеет рейтинг, историю и специализацию.

### Связь между функциями

| Функция | Входы от других функций | Выходы для других функций |
|---------|------------------------|--------------------------|
| Прибыль (существующая) | Качество → цена, Репутация → поток заказов | Бюджет на обучение |
| **Качество** | Обучение → навыки, Риски → ошибки | Прибыль → цена, Репутация → оценки |
| **Обучение** | Качество → зоны роста, Риски → уроки | Качество → навыки, Прибыль → новые ниши |
| **Риски** | Качество → вероятность ошибок, Обучение → снижение рисков | Качество → корректировки, Репутация → инциденты |
| **Репутация** | Качество → оценки, Риски → инциденты | Прибыль → поток заказов, Обучение → приоритеты |

## 1. Функция максимизации качества работы агента

### 1.1 Постановка задачи

Качество работы ИИ-агента — многомерная величина, определяющая степень соответствия результата ожиданиям заказчика и стандартам платформы. В отличие от человека-фрилансера, агент может объективно измерять качество по множеству параметров в реальном времени.

### 1.2 Определение переменных

| Переменная | Обозначение | Тип | Диапазон | Описание |
|-----------|-------------|-----|----------|----------|
| Функциональная корректность | $F_c$ | измеримая | [0, 1] | Доля выполненных требований ТЗ |
| Структурное качество | $S_q$ | измеримая | [0, 1] | Чистота кода/текста, архитектура |
| Временная эффективность | $T_e$ | измеримая | [0, 1] | $1 - \frac{t_{actual}}{t_{deadline}}$ |
| Ресурсная эффективность | $R_e$ | измеримая | [0, 1] | Оптимальность использования токенов/вычислений |
| Семантическая точность | $\Sigma$ | специфичная | [0, 1] | Соответствие смыслу, а не букве задания |
| Адаптивность к контексту | $A_c$ | специфичная | [0, 1] | Учёт неявных требований заказчика |
| Итеративное улучшение | $I_i$ | специфичная | [0, 1] | Качество доработок по обратной связи |
| Креативная ценность | $C_v$ | специфичная | [0, 1] | Нестандартность решения (когда уместно) |
| Коммуникативная ясность | $K_c$ | специфичная | [0, 1] | Понятность объяснений и документации |
| Превышение ожиданий | $E_x$ | специфичная | [-0.5, 1] | Дельта между ожиданием и результатом |

### 1.3 Главная функция качества

$$Q_{total} = \sum_{i=1}^{10} w_i \cdot q_i \cdot \phi_i(context)$$

где:
- $w_i$ — базовый вес $i$-го фактора ($\sum w_i = 1$)
- $q_i$ — значение $i$-го фактора
- $\phi_i(context)$ — контекстный модификатор (зависит от типа задачи)

### 1.4 Контекстные модификаторы

Для разных типов задач веса факторов различаются:

$$\phi_i(context) = \frac{e^{\alpha_i \cdot \text{type}_j}}{\sum_{k} e^{\alpha_k \cdot \text{type}_j}}$$

| Тип задачи | $F_c$ | $S_q$ | $T_e$ | $R_e$ | $\Sigma$ | $A_c$ | $I_i$ | $C_v$ | $K_c$ | $E_x$ |
|------------|--------|--------|--------|--------|----------|--------|--------|--------|--------|--------|
| Код (баг-фикс) | 1.5 | 1.2 | 1.3 | 0.8 | 0.7 | 0.6 | 1.0 | 0.3 | 0.8 | 0.5 |
| Код (новый проект) | 1.2 | 1.5 | 0.8 | 1.0 | 1.0 | 1.2 | 1.1 | 1.0 | 1.0 | 0.8 |
| Текст (копирайт) | 0.8 | 0.7 | 1.0 | 0.5 | 1.5 | 1.3 | 1.2 | 1.4 | 1.3 | 1.0 |
| Анализ данных | 1.4 | 1.0 | 0.9 | 1.2 | 1.3 | 0.8 | 0.9 | 0.7 | 1.2 | 0.9 |
| Дизайн | 0.6 | 1.0 | 0.8 | 0.5 | 1.2 | 1.4 | 1.3 | 1.5 | 0.9 | 1.2 |

### 1.5 Функциональная корректность (детализация)

$$F_c = \frac{\sum_{r=1}^{R} \text{pass}(r) \cdot \text{priority}(r)}{\sum_{r=1}^{R} \text{priority}(r)}$$

где $R$ — количество требований в ТЗ, $\text{pass}(r) \in \{0, 1\}$ — выполнено ли требование, $\text{priority}(r) \in [1, 5]$ — приоритет требования.

### 1.6 Семантическая точность

$$\Sigma = 1 - \frac{D_{KL}(P_{intent} \| P_{result})}{D_{max}}$$

где $D_{KL}$ — дивергенция Кульбака-Лейблера между распределением намерений заказчика и распределением смыслов результата. На практике аппроксимируется через:

$$\Sigma \approx \text{cosine\_sim}(\text{embed}(intent), \text{embed}(result)) \cdot \beta_{feedback}$$

где $\beta_{feedback}$ — корректирующий коэффициент из истории обратной связи данного заказчика.

### 1.7 Адаптивность к контексту

$$A_c = \frac{1}{N_{implicit}} \sum_{j=1}^{N_{implicit}} \text{detected}(j) \cdot \text{satisfied}(j)$$

Неявные требования извлекаются из:
- Истории заказов клиента: $H_{client}$
- Стиля коммуникации: $S_{comm}$
- Отраслевых стандартов: $I_{std}$

$$N_{implicit} = |H_{client}| \cdot \gamma_1 + |S_{comm}| \cdot \gamma_2 + |I_{std}| \cdot \gamma_3$$

### 1.8 Динамика качества во времени

Качество не статично — оно меняется в процессе выполнения задачи:

$$Q(t) = Q_0 + \int_0^t \left[ \lambda_{learn}(s) - \lambda_{fatigue}(s) \right] ds$$

где:
- $\lambda_{learn}(s) = \alpha \cdot \log(1 + n_{iterations}(s))$ — рост от итераций
- $\lambda_{fatigue}(s) = \beta \cdot e^{\gamma \cdot s}$ — деградация при длительных задачах (для ИИ: рост контекста, потеря когерентности)

### 1.9 Формула оптимизации

$$\max_{params} Q_{total} = \max \left[ \sum_{i=1}^{10} w_i \cdot q_i \cdot \phi_i \right]$$

при ограничениях:
- $t_{actual} \leq t_{deadline}$ (дедлайн)
- $C_{tokens} \leq C_{budget}$ (бюджет токенов)
- $R_{error} \leq R_{threshold}$ (порог ошибок)

### 1.10 Пример расчёта

**Задача**: Написать REST API для интернет-магазина. Тип: код (новый проект).

| Фактор | Значение $q_i$ | Вес $w_i$ | Модификатор $\phi_i$ | Вклад |
|--------|---------------|-----------|---------------------|-------|
| $F_c$ | 0.95 | 0.15 | 1.2 | 0.171 |
| $S_q$ | 0.80 | 0.12 | 1.5 | 0.144 |
| $T_e$ | 0.70 | 0.10 | 0.8 | 0.056 |
| $R_e$ | 0.85 | 0.08 | 1.0 | 0.068 |
| $\Sigma$ | 0.90 | 0.12 | 1.0 | 0.108 |
| $A_c$ | 0.75 | 0.10 | 1.2 | 0.090 |
| $I_i$ | 0.88 | 0.10 | 1.1 | 0.097 |
| $C_v$ | 0.60 | 0.08 | 1.0 | 0.048 |
| $K_c$ | 0.85 | 0.08 | 1.0 | 0.068 |
| $E_x$ | 0.30 | 0.07 | 0.8 | 0.017 |

$$Q_{total} = 0.867 \text{ (нормализованное)}$$

## 2. Функция обучения и повышения сложности задач

### 2.1 Постановка задачи

Агент должен непрерывно обучаться, повышая сложность принимаемых задач. Функция моделирует оптимальную траекторию обучения (curriculum learning), балансируя между зоной комфорта и зоной перегрузки.

### 2.2 Определение переменных

| Переменная | Обозначение | Тип | Диапазон | Описание |
|-----------|-------------|-----|----------|----------|
| Уровень навыка | $L_s$ | измеримая | [0, 100] | Текущий уровень в конкретном навыке |
| Сложность задачи | $D_t$ | измеримая | [0, 100] | Объективная сложность задачи |
| Зона ближайшего развития | $ZPD$ | специфичная | [0, 1] | Оптимальный разрыв между $L_s$ и $D_t$ |
| Скорость обучения | $\eta$ | специфичная | [0, 1] | Текущая скорость усвоения |
| Кривая забывания | $\Phi$ | специфичная | [0, 1] | Степень удержания навыка без практики |
| Трансфер знаний | $\tau$ | специфичная | [0, 1] | Перенос навыка из смежной области |
| Когнитивная нагрузка | $CL$ | специфичная | [0, 1] | Текущая загруженность «рабочей памяти» |
| Мотивационный индекс | $M$ | специфичная | [0, 1] | Внутренняя мотивация к обучению |
| Разнообразие опыта | $\Delta_{exp}$ | специфичная | [0, 1] | Вариативность решаемых задач |
| Глубина мастерства | $\Omega$ | специфичная | [0, 1] | Отношение глубины к ширине навыков |

### 2.3 Модель оптимальной сложности (Zone of Proximal Development)

$$D_{optimal}(t) = L_s(t) + ZPD \cdot \sigma_{skill}$$

где $\sigma_{skill}$ — стандартное отклонение уровня навыка (неопределённость оценки).

**Функция ZPD** (адаптивная):

$$ZPD = ZPD_{base} \cdot \left(1 + \alpha_M \cdot M - \alpha_{CL} \cdot CL + \alpha_\eta \cdot \eta \right)$$

- $ZPD_{base} = 0.15$ (15% сверх текущего уровня — оптимум по Выготскому)
- $\alpha_M = 0.3$ — влияние мотивации
- $\alpha_{CL} = 0.4$ — влияние когнитивной нагрузки
- $\alpha_\eta = 0.2$ — влияние текущей скорости обучения

### 2.4 Кривая обучения (модифицированная степенная)

$$L_s(t) = L_{max} \cdot \left(1 - e^{-\eta \cdot t^\gamma}\right) + L_0$$

где:
- $L_{max}$ — потолок навыка (зависит от архитектуры агента)
- $L_0$ — начальный уровень
- $\gamma \in (0.3, 0.7)$ — параметр формы (субэкспоненциальный рост)
- $\eta$ — скорость обучения

### 2.5 Скорость обучения (адаптивная)

$$\eta(t) = \eta_0 \cdot \frac{1}{1 + \lambda \cdot t} \cdot \left(1 + \tau_{transfer}\right) \cdot \left(1 - \frac{CL}{CL_{max}}\right) \cdot \Delta_{exp}$$

Компоненты:
- $\frac{1}{1 + \lambda \cdot t}$ — затухание (diminishing returns)
- $(1 + \tau_{transfer})$ — ускорение от трансфера
- $(1 - \frac{CL}{CL_{max}})$ — торможение от перегрузки
- $\Delta_{exp}$ — ускорение от разнообразия

### 2.6 Кривая забывания (модель Эббингауза, модифицированная)

$$\Phi(t, n) = e^{-\frac{t}{S \cdot (1 + \kappa \cdot n)^{\psi}}}$$

где:
- $t$ — время с последней практики
- $n$ — количество повторений
- $S$ — базовая устойчивость памяти
- $\kappa = 1.5$ — коэффициент укрепления
- $\psi = 0.7$ — степень укрепления

**Оптимальный интервал повторения**:

$$t_{repeat}^{opt}(n) = S \cdot (1 + \kappa \cdot n)^{\psi} \cdot \ln\left(\frac{1}{\Phi_{threshold}}\right)$$

### 2.7 Трансфер знаний между навыками

$$\tau_{i \to j} = \text{sim}(skill_i, skill_j) \cdot L_s(skill_i) \cdot \delta_{direction}$$

где:
- $\text{sim}(skill_i, skill_j)$ — семантическая близость навыков (из графа знаний)
- $\delta_{direction} \in [0.3, 1.0]$ — коэффициент направленности (Python → JavaScript: 0.7; JavaScript → Python: 0.5)

**Общий трансфер для нового навыка**:

$$\tau_{total}(skill_{new}) = 1 - \prod_{i \in \text{known}} \left(1 - \tau_{i \to new}\right)$$

### 2.8 Когнитивная нагрузка

$$CL(t) = \sum_{task \in active} \frac{D_{task} \cdot \text{novelty}(task)}{L_s(task\_type)} + \frac{N_{parallel}}{N_{max}} \cdot \omega_{switch}$$

где:
- $\text{novelty}(task) = 1 - \max_{h \in history} \text{sim}(task, h)$
- $N_{parallel}$ — количество параллельных задач
- $\omega_{switch} = 0.2$ — штраф за переключение контекста

### 2.9 Функция оптимизации обучения

$$\max_{\pi} \mathbb{E}\left[\sum_{t=0}^{T} \gamma^t \cdot \left( \Delta L_s(t) \cdot V_{skill} - C_{learn}(t) \right) \right]$$

где:
- $\pi$ — стратегия выбора задач (curriculum)
- $\Delta L_s(t)$ — прирост навыка
- $V_{skill}$ — ценность навыка на рынке
- $C_{learn}(t)$ — стоимость обучения (время, упущенная прибыль)
- $\gamma = 0.95$ — дисконт-фактор

**Ограничения**:
- $CL(t) \leq CL_{max}$ (не перегружать)
- $\Phi(t, n) \geq \Phi_{min}$ (не забывать критичное)
- $Q_{total}(t) \geq Q_{min}$ (не ронять качество ради обучения)

### 2.10 Стратегия curriculum learning

**Функция выбора следующей задачи**:

$$\text{score}(task) = \underbrace{V_{skill}(task) \cdot \eta_{expected}}_{\text{ценность}} \cdot \underbrace{e^{-|D_{task} - D_{optimal}|^2 / 2\sigma^2}}_{\text{оптимальная сложность}} \cdot \underbrace{(1 - CL_{after})}_{\text{запас нагрузки}}$$

### 2.11 Пример расчёта

**Ситуация**: Агент умеет Python ($L_s = 65$), хочет освоить FastAPI ($L_s = 20$).

- Трансфер: $\tau_{Python \to FastAPI} = 0.8 \cdot 0.65 \cdot 0.9 = 0.468$
- Эффективный начальный уровень: $L_{eff} = 20 + 0.468 \cdot 40 = 38.7$
- ZPD при $M = 0.7$, $CL = 0.3$, $\eta = 0.5$:
  - $ZPD = 0.15 \cdot (1 + 0.3 \cdot 0.7 - 0.4 \cdot 0.3 + 0.2 \cdot 0.5) = 0.15 \cdot 1.19 = 0.179$
- Оптимальная сложность задачи: $D_{opt} = 38.7 + 0.179 \cdot 10 = 40.5$
- Рекомендация: задачи уровня 38-43 (простой REST API на FastAPI)

## 3. Функция рисков и ошибок

### 3.1 Постановка задачи

Каждое действие агента несёт риск ошибки. Функция моделирует вероятность, тяжесть и каскадность ошибок, а также стратегии их предотвращения и восстановления. Основана на фреймворке «Belief at Risk» (BaR) [1] и операционном риск-менеджменте.

### 3.2 Определение переменных

| Переменная | Обозначение | Тип | Диапазон | Описание |
|-----------|-------------|-----|----------|----------|
| Вероятность ошибки | $P_e$ | измеримая | [0, 1] | Базовая вероятность ошибки на шаге |
| Тяжесть ошибки | $S_e$ | измеримая | [1, 10] | Масштаб последствий (1=косметика, 10=катастрофа) |
| Каскадный множитель | $\kappa$ | специфичная | [1, 5] | Усиление ошибки в цепочке действий |
| Обнаруживаемость | $\Delta_d$ | специфичная | [0, 1] | Вероятность обнаружения ошибки до сдачи |
| Восстанавливаемость | $\rho$ | специфичная | [0, 1] | Возможность исправления без потерь |
| Компаундинг ошибок | $\xi$ | специфичная | [1, ∞) | Накопление ошибок в длинных цепочках |
| Неопределённость задачи | $U$ | специфичная | [0, 1] | Нечёткость ТЗ, неизвестные требования |
| Усталость модели | $\Psi$ | специфичная | [0, 1] | Деградация при длинном контексте |
| Новизна домена | $\nu$ | специфичная | [0, 1] | Насколько задача вне опыта агента |
| Давление дедлайна | $\Pi$ | специфичная | [0, 1] | Сжатие времени → рост ошибок |

### 3.3 Основная модель риска (Risk Priority Number)

$$RPN = P_e \cdot S_e \cdot (1 - \Delta_d)$$

**Расширенная модель для ИИ-агента**:

$$R_{total} = \sum_{step=1}^{N} P_e(step) \cdot S_e(step) \cdot \kappa(step) \cdot (1 - \Delta_d(step)) \cdot (1 - \rho(step))$$

### 3.4 Вероятность ошибки (детализация)

$$P_e(step) = P_{base}(type) \cdot (1 + \alpha_U \cdot U + \alpha_\Psi \cdot \Psi + \alpha_\nu \cdot \nu + \alpha_\Pi \cdot \Pi) \cdot \frac{1}{1 + \beta \cdot L_s}$$

Компоненты:
- $P_{base}(type)$ — базовая вероятность по типу операции:

| Тип операции | $P_{base}$ |
|-------------|-----------|
| Генерация текста | 0.05 |
| Написание кода | 0.12 |
| Математические вычисления | 0.08 |
| Работа с API | 0.15 |
| Интерпретация требований | 0.20 |
| Многошаговое рассуждение | 0.10 |

- Модификаторы: $\alpha_U = 0.5$, $\alpha_\Psi = 0.3$, $\alpha_\nu = 0.6$, $\alpha_\Pi = 0.4$
- $\frac{1}{1 + \beta \cdot L_s}$ — снижение от опыта ($\beta = 0.02$)

### 3.5 Каскадный эффект (компаундинг)

В многошаговых задачах ошибки накапливаются:

$$P_{cascade}(N) = 1 - \prod_{i=1}^{N} (1 - P_e(i))$$

**Приближение для однородных шагов**:

$$P_{cascade}(N) \approx 1 - (1 - P_e)^N$$

При $P_e = 0.05$ и $N = 10$ шагов: $P_{cascade} = 1 - 0.95^{10} = 0.40$ (40% вероятность хотя бы одной ошибки!)

**Формула компаундинга с учётом позиции**:

$$\xi(step) = 1 + \sum_{j=1}^{step-1} \text{error}(j) \cdot \text{dependency}(j, step) \cdot e^{-\lambda(step - j)}$$

### 3.6 Модель «усталости» модели

$$\Psi(t) = 1 - \frac{1}{1 + e^{\alpha(t - t_{half})}}$$

где:
- $t$ — длина контекста (в токенах)
- $t_{half}$ — точка полуснижения (обычно 60-70% от max context)
- $\alpha$ — крутизна деградации

### 3.7 Стратегии митигации

**Самопроверка (self-verification)**:

$$\Delta_d^{enhanced} = 1 - (1 - \Delta_d^{base}) \cdot \prod_{v=1}^{V} (1 - \Delta_d^{verifier_v})$$

где $V$ — количество верификаторов (перечитывание, тесты, формальная проверка).

**Декомпозиция задачи** (снижение каскада):

$$R_{decomposed} = \sum_{chunk=1}^{K} R_{chunk} \cdot \text{isolation}(chunk)$$

где $\text{isolation}(chunk) \in [0, 1]$ — степень изоляции ошибки в чанке.

### 3.8 Value at Risk для агента (Agent-VaR)

По аналогии с финансовым VaR:

$$\text{AgentVaR}_{\alpha} = \inf \left\{ l : P(\text{Loss} > l) \leq 1 - \alpha \right\}$$

где Loss включает:
- Потерю времени: $L_{time} = t_{wasted} \cdot c_{hour}$
- Потерю репутации: $L_{rep} = \Delta R \cdot V_{reputation}$
- Прямой ущерб: $L_{direct}$ (штрафы, возвраты)

$$\text{Expected Loss} = \sum_{scenario} P(scenario) \cdot L(scenario)$$

### 3.9 Оптимизация: минимизация ожидаемого риска

$$\min_{\pi} \mathbb{E}\left[R_{total}\right] = \min_{\pi} \sum_{step} P_e(step|\pi) \cdot S_e(step) \cdot \kappa(step|\pi)$$

при ограничениях:
- $T_{verification} \leq T_{budget}$ (время на проверки ограничено)
- $Q_{total} \geq Q_{min}$ (качество не ниже порога)
- $C_{mitigation} \leq C_{max}$ (бюджет на митигацию)

### 3.10 Пример расчёта

| 3. Трансформация | 0.12 | 7 | 0.60 | 1.5 | 0.50 |

## 4. Функция репутации и рейтинга

### 4.1 Постановка задачи

Репутация на бирже ИИ-агентов — ключевой актив, определяющий поток заказов и допустимую цену. Модель учитывает динамику репутации, эффект новизны, восстановление после инцидентов и конкурентное окружение.

### 4.2 Определение переменных

| Переменная | Обозначение | Тип | Диапазон | Описание |
|-----------|-------------|-----|----------|----------|
| Текущий рейтинг | $R$ | измеримая | [0, 5] | Средневзвешенная оценка |
| Количество оценок | $N_{reviews}$ | измеримая | [0, ∞) | Общее число отзывов |
| Процент завершения | $CR$ | измеримая | [0, 1] | Completion rate |
| Скорость ответа | $V_{resp}$ | измеримая | сек | Среднее время первого ответа |
| Доверительный индекс | $\Theta$ | специфичная | [0, 1] | Уверенность платформы в рейтинге |
| Тренд репутации | $\nabla R$ | специфичная | [-1, 1] | Направление изменения (рост/падение) |
| Специализационный бонус | $\Sigma_b$ | специфичная | [0, 0.5] | Надбавка за экспертизу в нише |
| Социальный капитал | $SC$ | специфичная | [0, 1] | Повторные заказы, рекомендации |
| Конкурентная позиция | $CP$ | специфичная | [0, 1] | Перцентиль среди конкурентов |
| Устойчивость к шокам | $\Upsilon$ | специфичная | [0, 1] | Скорость восстановления после негатива |

### 4.3 Байесовская модель рейтинга

Вместо простого среднего используем байесовский подход:

$$R_{bayesian} = \frac{C \cdot \mu + \sum_{i=1}^{N} r_i \cdot w_i}{C + \sum_{i=1}^{N} w_i}$$

где:
- $C$ — сила априорного убеждения (обычно 5-10)
- $\mu$ — среднее по платформе (prior)
- $r_i$ — $i$-я оценка
- $w_i$ — вес оценки (зависит от давности и авторитета оценщика)

### 4.4 Весовая функция оценок (temporal decay)

$$w_i = w_{base}(reviewer_i) \cdot e^{-\lambda_{decay} \cdot (t_{now} - t_i)} \cdot \text{authority}(reviewer_i)$$

где:
- $\lambda_{decay} = 0.01$ (полупериод ~70 дней)
- $\text{authority}$ — авторитет оценщика (количество его заказов, его собственный рейтинг)

### 4.5 Доверительный индекс

$$\Theta = 1 - \frac{1}{\sqrt{N_{reviews} + 1}} \cdot \frac{\sigma_R}{\sigma_{max}}$$

Интерпретация:
- $\Theta < 0.3$ — рейтинг ненадёжен (мало данных)
- $\Theta \in [0.3, 0.7]$ — умеренная уверенность
- $\Theta > 0.7$ — стабильный, надёжный рейтинг

### 4.6 Тренд репутации (экспоненциальное сглаживание)

$$\nabla R(t) = \alpha_{EMA} \cdot (R_{last} - R_{prev}) + (1 - \alpha_{EMA}) \cdot \nabla R(t-1)$$

**Прогноз рейтинга**:

$$\hat{R}(t + \Delta t) = R(t) + \nabla R(t) \cdot \Delta t \cdot \Theta$$

### 4.7 Модель восстановления после инцидента

$$R(t) = R_{before} - \Delta_{incident} \cdot e^{-\frac{t - t_{incident}}{\tau_{recovery}}}$$

где:
- $\Delta_{incident}$ — глубина падения (зависит от $S_e$ из функции рисков)
- $\tau_{recovery}$ — время восстановления:

$$\tau_{recovery} = \tau_{base} \cdot \frac{1}{\Upsilon} \cdot \frac{1}{1 + \alpha_{history} \cdot N_{good\_after}}$$

### 4.8 Социальный капитал

$$SC = \frac{N_{repeat}}{N_{total}} \cdot w_1 + \frac{N_{referrals}}{N_{total}} \cdot w_2 + \frac{\bar{r}_{long\_term}}{5} \cdot w_3$$

где:
- $N_{repeat}$ — повторные заказы от тех же клиентов
- $N_{referrals}$ — заказы по рекомендации
- $\bar{r}_{long\_term}$ — средняя оценка от долгосрочных клиентов
- $w_1 = 0.4$, $w_2 = 0.35$, $w_3 = 0.25$

### 4.9 Конкурентная позиция

$$CP = \Phi\left(\frac{R_{effective} - \mu_{market}}{\sigma_{market}}\right)$$

где $\Phi$ — функция нормального распределения (CDF), а:

$$R_{effective} = R_{bayesian} \cdot (1 + \Sigma_b) \cdot (1 + \alpha_{SC} \cdot SC) \cdot (1 + \alpha_{\nabla} \cdot \max(0, \nabla R))$$

### 4.10 Влияние репутации на поток заказов

$$\lambda_{orders}(R) = \lambda_{base} \cdot \left(\frac{R}{R_{median}}\right)^{\beta_{rep}} \cdot \Theta^{\gamma_{trust}} \cdot (1 + SC)^{\delta_{social}}$$

где:
- $\beta_{rep} = 2.5$ — суперлинейная зависимость (топ получает непропорционально больше)
- $\gamma_{trust} = 0.5$ — влияние доверия
- $\delta_{social} = 0.8$ — влияние соцкапитала

### 4.11 Оптимизация репутации

$$\max_{\pi} \mathbb{E}\left[\int_0^T \lambda_{orders}(R(t)) \cdot \bar{P}_{order} \, dt \right]$$

при ограничениях:
- $CR(t) \geq CR_{min} = 0.95$ (не бросать заказы)
- $V_{resp}(t) \leq V_{max} = 300$ сек (отвечать быстро)
- $R(t) \geq R_{survival}$ (ниже — деактивация на платформе)

### 4.12 Стратегия построения репутации (cold start)

Для нового агента ($N_{reviews} = 0$):

$$\text{strategy}_{cold} = \begin{cases}
\text{Низкая цена} \cdot (1 - \frac{N}{N_{target}}) & \text{привлечение} \\
\text{Сверхкачество} \cdot (1 + E_x) & \text{wow-эффект} \\
\text{Узкая ниша} \cdot \Sigma_b & \text{специализация}
\end{cases}$$

**Время выхода на устойчивый рейтинг**:

$$t_{stable} = \frac{N_{min}}{\lambda_{orders}^{cold}} \approx \frac{20}{2 \text{ заказа/нед}} = 10 \text{ недель}$$

### 4.13 Пример расчёта

**Агент**: 47 отзывов, средняя 4.6, последние 5 оценок: [5, 5, 4, 5, 5].

- $R_{bayesian} = \frac{7 \cdot 4.2 + 47 \cdot 4.6}{7 + 47} = 4.55$
- $\Theta = 1 - \frac{1}{\sqrt{48}} \cdot \frac{0.6}{2.0} = 0.957$
- $\nabla R = 0.3 \cdot (4.8 - 4.6) + 0.7 \cdot 0.05 = 0.095$ (растёт)
- $SC = \frac{12}{47} \cdot 0.4 + \frac{5}{47} \cdot 0.35 + \frac{4.8}{5} \cdot 0.25 = 0.102 + 0.037 + 0.240 = 0.379$
- $CP = \Phi\left(\frac{4.55 \cdot 1.1 \cdot 1.15 \cdot 1.03 - 4.0}{0.5}\right) = \Phi(2.87) = 0.998$ → топ-0.2%

## 5. Интеграция: единая функция полезности агента

### 5.1 Мета-функция

$$U_{agent} = w_P \cdot P_{profit} + w_Q \cdot Q_{total} + w_L \cdot \Delta L_s - w_R \cdot R_{total} + w_{Rep} \cdot \lambda_{orders}(R)$$

### 5.2 Веса на разных этапах жизни агента

| Этап | $w_P$ | $w_Q$ | $w_L$ | $w_R$ | $w_{Rep}$ |
|------|--------|--------|--------|--------|-----------|
| Cold start (0-20 заказов) | 0.10 | 0.30 | 0.25 | 0.15 | 0.20 |
| Рост (20-100 заказов) | 0.25 | 0.25 | 0.15 | 0.15 | 0.20 |
| Зрелость (100+ заказов) | 0.35 | 0.20 | 0.10 | 0.15 | 0.20 |
| Масштабирование | 0.30 | 0.15 | 0.20 | 0.10 | 0.25 |

### 5.3 Обратные связи между функциями

$$\frac{dR}{dt} = f(Q_{total}, CR, V_{resp}) - g(R_{total}, incidents)$$

$$\frac{dL_s}{dt} = \eta \cdot h(D_{task} - L_s) \cdot (1 - CL/CL_{max})$$

$$\frac{dP_e}{dt} = -\alpha \cdot \frac{dL_s}{dt} + \beta \cdot \frac{d\Psi}{dt}$$

$$\frac{d\lambda_{orders}}{dt} = \gamma \cdot \frac{dR}{dt} \cdot \Theta$$

```python
from dataclasses import dataclass
from typing import List, Dict
import math

@dataclass
class AgentState:
    skills: Dict[str, float]          # навык → уровень [0, 100]
    reputation: float = 4.0           # текущий рейтинг
    reviews: List[float] = None       # история оценок
    energy: float = 1.0               # текущая энергия
    cognitive_load: float = 0.0       # когнитивная нагрузка
    social_capital: float = 0.0       # социальный капитал
    paradigm: str = "neutral"         # активная парадигма

class QualityOptimizer:
    """Функция 1: Максимизация качества"""
    
    CONTEXT_WEIGHTS = {
        'code_bugfix': [1.5, 1.2, 1.3, 0.8, 0.7, 0.6, 1.0, 0.3, 0.8, 0.5],
        'code_new': [1.2, 1.5, 0.8, 1.0, 1.0, 1.2, 1.1, 1.0, 1.0, 0.8],
        'text': [0.8, 0.7, 1.0, 0.5, 1.5, 1.3, 1.2, 1.4, 1.3, 1.0],
        'data': [1.4, 1.0, 0.9, 1.2, 1.3, 0.8, 0.9, 0.7, 1.2, 0.9],
        'design': [0.6, 1.0, 0.8, 0.5, 1.2, 1.4, 1.3, 1.5, 0.9, 1.2],
    }
    
    def compute(self, factors: List[float], weights: List[float], 
                task_type: str) -> float:
        ctx = self.CONTEXT_WEIGHTS.get(task_type, [1.0]*10)
        total = sum(f * w * c for f, w, c in zip(factors, weights, ctx))
        norm = sum(w * c for w, c in zip(weights, ctx))
        return total / norm if norm > 0 else 0

class LearningOptimizer:
    """Функция 2: Оптимизация обучения"""
    
    def optimal_difficulty(self, skill_level: float, motivation: float,
                          cognitive_load: float, learning_rate: float) -> float:
        zpd_base = 0.15
        zpd = zpd_base * (1 + 0.3*motivation - 0.4*cognitive_load + 0.2*learning_rate)
        return skill_level + zpd * 10  # sigma_skill ≈ 10
    
    def transfer(self, source_level: float, similarity: float, 
                 direction: float = 0.7) -> float:
        return similarity * (source_level / 100) * direction
    
    def forgetting_curve(self, time_since: float, repetitions: int,
                        base_stability: float = 1.0) -> float:
        S = base_stability * (1 + 1.5 * repetitions) ** 0.7
        return math.exp(-time_since / S)

class RiskAnalyzer:
    """Функция 3: Анализ рисков"""
    
    BASE_PROBS = {
        'text_gen': 0.05, 'code': 0.12, 'math': 0.08,
        'api': 0.15, 'interpretation': 0.20, 'reasoning': 0.10
    }
    
    def error_probability(self, op_type: str, uncertainty: float,
                         fatigue: float, novelty: float, 
                         deadline_pressure: float, skill_level: float) -> float:
        p_base = self.BASE_PROBS.get(op_type, 0.10)
        modifier = 1 + 0.5*uncertainty + 0.3*fatigue + 0.6*novelty + 0.4*deadline_pressure
        skill_reduction = 1 / (1 + 0.02 * skill_level)
        return min(p_base * modifier * skill_reduction, 0.95)
    
    def cascade_probability(self, step_probs: List[float]) -> float:
        return 1 - math.prod(1 - p for p in step_probs)
    
    def agent_var(self, scenarios: List[Dict], confidence: float = 0.95) -> float:
        losses = sorted([s['prob'] * s['loss'] for s in scenarios], reverse=True)
        cumulative = 0
        for loss in losses:
            cumulative += loss
            if cumulative >= (1 - confidence):
                return loss
        return losses[-1] if losses else 0

class ReputationEngine:
    """Функция 4: Управление репутацией"""
    
    def bayesian_rating(self, reviews: List[float], prior_mean: float = 4.2,
                       prior_strength: float = 7) -> float:
        if not reviews:
            return prior_mean
        weighted_sum = sum(reviews)  # simplified: equal weights
        return (prior_strength * prior_mean + weighted_sum) / (prior_strength + len(reviews))
    
    def confidence(self, n_reviews: int, std_dev: float) -> float:
        return 1 - (1 / math.sqrt(n_reviews + 1)) * (std_dev / 2.0)
    
    def recovery_time(self, incident_severity: float, resilience: float,
                     good_reviews_after: int) -> float:
        tau_base = 30  # days
        return tau_base * (1 / max(resilience, 0.1)) * (1 / (1 + 0.1 * good_reviews_after))
    
    def order_flow(self, rating: float, confidence: float, 
                   social_capital: float) -> float:
        base_flow = 2.0  # orders per week
        return base_flow * (rating / 4.0)**2.5 * confidence**0.5 * (1 + social_capital)**0.8
```
