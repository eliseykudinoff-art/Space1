## 🔑 Ключевые решения (и их обоснование)

### Решение 1: Γ(·) — Отдельная функция VETO

**Проблема:** Смешивание compliance с optimization семантически некорректно.

**Решение:** Γ(·) — это HARD CONSTRAINT, не objective function.
- Γ = FAIL → REJECT без дальнейшего рассмотрения
- Γ = PASS → продолжаем вычисления

**Обоснование:** 
- Legal/compliance violations — это не оптимизируемые параметры
- Штраф за нарушение ≠ бесконечности ≠ невозможность действия
- VETO семантически точнее

### Решение 2: M(·) — Policy, не Optimization

**Проблема:** "Mission" звучит как цель, но это не optimization target.

**Решение:** Mission.calibrate() возвращает:
- λ_* веса (ОТНОШЕНИЕ к функциям)
- q_min, ψ_max пороги (ЧТО допустимо)
- Γ_rules (ЧТО НЕЛЬЗЯ)

**Обоснование:**
- Mission определяет "кто я такой", не "что максимизировать"
- Это калибровка, не gradient descent
- Веса не оптимизируются напрямую, а выводятся из принципов

### Решение 3: Υ(·) и Ω(·) — Отдельные функции

**Проблема:** Репутация и эволюция смешивались с прибылью.

**Решение:** Υ и Ω — отдельные objective functions с собственными dynamics.

**Обоснование:**
- Υ (репутация) — долгосрочный asset с другой dynamics
- Ω (эволюция) — на других timescales
- Не должны "конкурировать" за веса с Φ

### Решение 4: E(·) — Не отдельная функция

**Проблема:** Функция ошибок предлагалась как отдельная.

**Решение:** E(·) — это diagnostic, не controlling function.

**Обоснование:**
- E = f(Q, Ψ) — уже покрыто качеством и риском
- Полезна для аналитики, но не для принятия решений
- Decision: include as metric, not as function

### Решение 5: B(·) — Скрытая функция

**Проблема:** Байесовская оптимизация весов — это meta-learning.

**Решение:** B(·) — hidden, не влияет на decision flow напрямую.

**Обоснование:**
- B обновляет параметры других функций
- Работает в фоне, не блокирует основной flow
- Скрыта от Orchestrator

```python
            - novelty_in_environment,       # Новое в среде
            - unanswered_questions,         # Неизвестное
            - potential_opportunities,      # Возможности
            - boredom_level                # Скука
        )
        """
        curiosity = (
            self.config.alpha_time * (now() - state.last_exploration) +
            self.config.alpha_novelty * state.novelty_level +
            self.config.alpha_opportunities * state.opportunity_potential
        )
        
        return curiosity
    
    def should_explore(self, curiosity: float) -> bool:
        """
        Бинарный сигнал: пора исследовать или нет
        """
        return curiosity > self.threshold


class ExplorationManager:
    """
    Управляет исследовательским поведением
    """
    
    def on_curiosity_signal(self, signal: bool):
        if signal:
            # Генерируем exploration task
            task = self.generate_exploration_task()
            
            # Отправляем в Orchestrator
            decision = self.orchestrator.evaluate(task)
            
            if decision.action == "EXECUTE":
                self.execute_exploration(task)
```

### Тезис 7: Цепочка действий без LLM

**Ключевая идея:** LLM = переводчик, не планировщик

```
ПРОБЛЕМА:
Большинство агентов:  LLM генерирует план (медленно, дорого, ненадёжно)
                      "Давай сделаем 5 шагов..."

НАШ ПОДХОД:
LLM: переводит задачу в структурированный формат
Orchestrator: моделирует цепочку действий (fast, cheap, precise)

```

```python
class ActionChainPlanner:
    """
    Планирование цепочки действий — БЕЗ LLM
    
    Input:  Первичный импульс (binary signal)
    Output: Последовательность atomic operations
    
    Основа:
    - Predefined action templates
    - State machine для известных сценариев
    - Rule-based planning
    - Graph search (A* для complex cases)
    """
    
    def plan_from_impulse(
        self, 
        impulse: ImpulseSignal, 
        state: AgentState,
        constraints: Constraints
    ) -> ActionChain:
        """
        Трансформирует первичный импульс в цепочку действий
        
        Impulse → [Classification] → Scenario Type
                                  ↓
                          [Template Selection]
                                  ↓
                          [Parameter Binding]
                                  ↓
                          [Constraint Checking]
                                  ↓
                          [Action Chain]
        """
        # Шаг 1: Классифицируем импульс
        scenario_type = self.classify_impulse(impulse)
        
        # Шаг 2: Выбираем шаблон цепочки
        template = self.get_template(scenario_type)
        
        # Шаг 3: Привязываем параметры из состояния
        bound_chain = template.bind(state, constraints)
        
        # Шаг 4: Валидируем цепочку
        if self.validate_chain(bound_chain, constraints):
            return bound_chain
        
        # Шаг 5: Fallback — упрощаем
        return self.simplify_chain(bound_chain)


class ImpulseSignal:
    """
    Первичный импульс — бинарный сигнал к действию
    
    Типы импульсов:
    • CURIOUS: любопытство сработало
    • OPPORTUNITY: обнаружена возможность
    • WARNING: что-то требует внимания
    • DEADLINE: приближается срок
    • USER_REQUEST: входящая задача
    • SCHEDULED: сработал таймер
    """
    type: str
    intensity: float  # 0.0 - 1.0
    source: str
    timestamp: datetime
```

```python
class AgentScheduler:
    """
    Планировщик с двумя источниками trigger
    """
    
    def __init__(self, orchestrator: Orchestrator, llm: LLMInterface):
        self.orchestrator = orchestrator
        self.llm = llm
        
        # Внутренние метрики для проактивности
        self.curiosity_function = CuriosityFunction(...)
        self.risk_monitor = RiskMonitor(...)
        self.opportunity_scanner = OpportunityScanner(...)
        
        # Таймеры для scheduled tasks
        self.timers = CronScheduler(...)
    
    def run_loop(self):
        """
        Основной цикл агента
        """
        while True:
            # 1. Проверяем trigger sources
            triggers = self.check_triggers()
            
            if triggers:
                for trigger in triggers:
                    # 2. Генерируем импульс
                    impulse = self.create_impulse(trigger)
                    
                    # 3. Планируем цепочку
                    chain = self.planner.plan_from_impulse(
                        impulse,
                        self.state,
                        self.constraints
                    )
                    
                    # 4. Выполняем
                    self.execute_chain(chain)
            
            # 5. Sleep until next check
            time.sleep(self.check_interval)
    
    def check_triggers(self) -> List[Trigger]:
        """
        Проверяет все источники trigger
        """
        triggers = []
        
        # External triggers
        triggers.extend(self.check_external_queue())
        
        # Internal triggers
        if self.curiosity_function.should_explore():
            triggers.append(Trigger(type="CURIOUS", source="internal"))
        
        if self.risk_monitor.is_critical():
            triggers.append(Trigger(type="WARNING", source="internal"))
        
        if self.opportunity_scanner.detected():
            triggers.append(Trigger(type="OPPORTUNITY", source="internal"))
        
        # Scheduled triggers
        triggers.extend(self.timers.get_due())
        
        return triggers
```

### Дофаминовые сигналы — Reward Prediction Error

```
┌─────────────────────────────────────────────────────────────┐
│  DOPAMINE-LIKE SYSTEM                                       │
│                                                             │
│  Дофамин в мозге = reward-prediction error (RPE)            │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  RPE = Actual Reward - Expected Reward               │   │
│  │                                                     │   │
│  │  RPE > 0: "Ожидания превзойдены!" → УЧИТЬСЯ        │   │
│  │  RPE = 0: "Всё как ожидалось" → ничего             │   │
│  │  RPE < 0: "Хуже чем ожидал" → ИЗБЕГАТЬ            │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

**Интеграция с нашим Orchestrator:**

```python
class DopamineSignal:
    """
    Аналог дофамина для агента
    
    Используем для:
    - Обновления весов после результата
    - Обучения (B(·) Bayesian update)
    - Curiosity калибровки
    """
    
    def calculate_rpe(
        self,
        actual_outcome: float,
        expected_outcome: float
    ) -> float:
        """
        RPE = Actual - Expected
        
        Returns:
        > 0: Positive surprise → усилить поведение
        = 0: Expected → neutral
        < 0: Negative surprise → ослабить поведение
        """
        return actual_outcome - expected_outcome
    
    def on_outcome(
        self,
        task: Task,
        expected_metrics: Dict[str, float],
        actual_metrics: Dict[str, float]
    ):
        """
        Обработка результата задачи
        """
        rpe_scores = {}
        
        for metric, expected in expected_metrics.items():
            actual = actual_metrics.get(metric, 0)
            rpe_scores[metric] = self.calculate_rpe(actual, expected)
        
        # Агрегированный RPE
        total_rpe = self.weighted_aggregate(rpe_scores)
        
        # Обновляем Bayesian weights
        if total_rpe > 0:
            self.bayesian_optimizer.update_positive(task, total_rpe)
        elif total_rpe < 0:
            self.bayesian_optimizer.update_negative(task, total_rpe)
        
        return rpe_scores
```

```python
class CortisolSignal:
    """
    Кортизоловый стресс-сигнал
    
    Регулирует:
    - Скорость принятия решений
    - Толерантность к риску
    - Приоритет безопасности
    """
    
    def __init__(self):
        self.current_level = 0.0
        self.half_life_minutes = 30  # Кортизол медленно спадает
    
    def on_stress_event(self, event: StressEvent):
        """
        Реакция на стрессовое событие
        """
        if event.severity == "spike":
            # Немедленное повышение
            self.current_level = min(1.0, self.current_level + event.magnitude)
        elif event.severity == "gradual":
            # Постепенное накопление
            self.current_level += event.magnitude * 0.1
        
        return self.current_level
    
    def decay(self, minutes_elapsed: float):
        """
        Естественное снижение кортизола
        """
        decay_factor = 0.5 ** (minutes_elapsed / self.half_life_minutes)
        self.current_level *= decay_factor
    
    def get_modulation(self) -> StressModulation:
        """
        Возвращает модуляцию для других систем
        """
        return StressModulation(
            decision_speed=self._get_decision_speed(),
            risk_tolerance=self._get_risk_tolerance(),
            safety_priority=self._get_safety_priority(),
            exploration_drive=self._get_exploration_drive()
        )
```

```python
    decay_rate: float      # как быстро затухает

        self.intensity *= (1.0 - self.decay_rate)
```

### Homeostasis — Гомеостаз агента

```
┌─────────────────────────────────────────────────────────────┐

│                                                             │
│  Человек: температура тела ~36.6°C, глюкоза, etc          │

│                                                             │

│  │  HOMEOSTATIC SETPOINTS:                             │   │
│  │                                                     │   │

│  │  Quality:     0.8 ± 0.1                             │   │
│  │  Reputation:  0.7 ± 0.1                             │   │
│  │  Curiosity:   0.5 ± 0.2 (dynamic)                  │   │
│  │  Energy:      0.8 ± 0.1                             │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  REGULATION:                                               │

│  • Above setpoint → drive to reduce                        │

└─────────────────────────────────────────────────────────────┘
```

```python
class HomeostaticController:
    """
    Гомеостатический контроллер
    
    Поддерживает метрики агента в "нормальных" диапазонах
    """
    
    def __init__(self):
        self.setpoints = {
            "risk": Setpoint(target=0.3, tolerance=0.1),
            "quality": Setpoint(target=0.8, tolerance=0.1),
            "reputation": Setpoint(target=0.7, tolerance=0.1),
            "curiosity": Setpoint(target=0.5, tolerance=0.2),  # Динамический
            "energy": Setpoint(target=0.8, tolerance=0.1),
        }
    
    def get_regulatory_drive(self, metric: str, current: float) -> float:
        """
        Возвращает drive для восстановления баланса
        
        > 0: Need to increase
        < 0: Need to decrease
        """
        sp = self.setpoints[metric]
        deviation = current - sp.target
        
        if abs(deviation) <= sp.tolerance:
            return 0.0  # В норме
        
        # Proportional response
        return -deviation * self.gain  # Negative feedback
    
    def check_all(self, state: AgentState) -> Dict[str, RegulatoryDrive]:
        """
        Проверяет все метрики и возвращает drives
        """
        drives = {}
        for metric, sp in self.setpoints.items():
            current = getattr(state, metric, 0.5)
            drives[metric] = self.get_regulatory_drive(metric, current)
        
        return drives
```

```python
class DigitalHormoneSystem:
    """
    Система цифровых гормонов
    
    Гормоны = медленные модуляторы поведения
    """
    
    # Математика:
    # h_i(t+1) = h_i(t) + S_i(t) + R_i(h(t)) + D_i(neighbors) - κ_i * h_i(t)
    
    def __init__(self):
        # Slow-acting hormones with decay
        self.hormones = {
            "metabolic": Hormone(
                name="metabolic",
                base_level=0.5,
                production_rate=0.01,    # S_i(t)
                decay_rate=0.001,         # κ_i
                half_life_hours=12
            ),
            "growth": Hormone(
                name="growth",
                base_level=0.3,
                production_rate=0.005,
                decay_rate=0.0005,
                half_life_hours=24
            ),
            "melatonin": Hormone(
                name="melatonin",
                base_level=0.2,
                production_rate=0.02,
                decay_rate=0.01,
                half_life_hours=4,
                circadian=True  # Циклический
            ),
            "stress": Hormone(
                name="cortisol_like",
                base_level=0.1,
                production_rate=0.05,    # Высокий при стрессе
                decay_rate=0.02,         # Медленно спадает
                half_life_hours=6
            ),
        }
        
        # Пороги для взаимодействия гормонов
        self.genome = {
            # Пример: высокий стресс подавляет рост
            ("stress", "growth", "suppress"): 0.7,
            # Пример: melatonin влияет на активность
            ("melatonin", "activity", "inhibit"): 0.5,
        }
    
    def update(self, sensor_inputs: Dict[str, float]):
        """
        Обновление уровней гормонов
        """
        new_levels = {}
        
        for name, hormone in self.hormones.items():
            # 1. Секреция (сенсорно-триггерная)
            secretion = hormone.production_rate * sensor_inputs.get(name, 0)
            
            # 2. Гормон-гормон взаимодействия
            interactions = self._compute_interactions(name)
            
            # 3. Диффузия (если есть соседи)
            diffusion = self._compute_diffusion(name)
            
            # 4. Распад
            decay = hormone.decay_rate * hormone.current_level
            
            # 5. Новое значение
            new_levels[name] = (
                hormone.current_level + 
                secretion + 
                interactions + 
                diffusion - 
                decay
            )
            
            # 6. Ограничить (boundedness required for stability!)
            new_levels[name] = max(0.0, min(1.0, new_levels[name]))
        
        return new_levels
    
    def get_modulation(self) -> HormoneModulation:
        """
        Возвращает модуляцию для всех систем
        """
        return HormoneModulation(
            processing_speed=self._compute_speed(),
            resource_efficiency=self._compute_efficiency(),
            learning_rate=self._compute_learning(),
            activity_level=self._compute_activity(),
            stress_level=self.hormones["stress"].current_level
        )
```

```python
class HomeostaticController:
    """
    Гомеостатический контроллер
    
    Поддерживает метрики агента в "нормальных" диапазонах
    через negative feedback
    """
    
    def __init__(self):
        self.setpoints = {
            "risk": Setpoint(target=0.3, tolerance=0.1),
            "quality": Setpoint(target=0.8, tolerance=0.1),
            "reputation": Setpoint(target=0.7, tolerance=0.1),
            "curiosity": Setpoint(target=0.5, tolerance=0.2),  # Динамический
            "energy": Setpoint(target=0.8, tolerance=0.1),
            "budget": Setpoint(target=0.5, tolerance=0.2),
        }
        
        # Negative feedback gain
        self.gain = 2.0
        
        # Интегральная компонента (для устойчивости)
        self.integral_error = {k: 0.0 for k in self.setpoints}
    
    def get_regulatory_drive(self, metric: str, current: float) -> float:
        """
        Возвращает drive для восстановления баланса
        
        > 0: Need to increase (too low)
        < 0: Need to decrease (too high)
        """
        sp = self.setpoints[metric]
        error = sp.target - current  # Positive = too low
        
        if abs(error) <= sp.tolerance:
            return 0.0  # В норме
        
        # Proportional + Integral control
        self.integral_error[metric] += error
        proportional = -error * self.gain
        integral = -self.integral_error[metric] * 0.1  # Small integral
        
        return proportional + integral
    
    def check_all(self, state: AgentState) -> Dict[str, RegulatoryDrive]:
        """
        Проверяет все метрики и возвращает drives
        """
        drives = {}
        
        for metric, sp in self.setpoints.items():
            current = getattr(state, metric, sp.target)
            drives[metric] = RegulatoryDrive(
                metric=metric,
                current=current,
                target=sp.target,
                error=current - sp.target,
                drive=self.get_regulatory_drive(metric, current),
                in_tolerance=abs(current - sp.target) <= sp.tolerance
            )
        
        return drives
    
    def on_deviation(self, metric: str, deviation: float):
        """
        Обработка отклонения метрики
        
        Вызывается когда метрика выходит за tolerance
        """
        if metric == "risk":
            # Слишком высокий риск → Cortisol ↑ → осторожность
            self.hormone_system.produce("stress", amount=deviation)
            
        elif metric == "quality":
            # Качество падает → сигнал к улучшению
            self.trigger_action("quality_repair")
            
        elif metric == "curiosity":
            # Любопытство вне диапазона → исследовать или сфокусироваться
            if deviation < 0:
                self.trigger_action("seek_novelty")
            else:
                self.trigger_action("focus_exploitation")


class Setpoint:
    """
    Точка гомеостаза
    """
    target: float       # Идеальное значение
    tolerance: float   # Допустимое отклонение
    min_value: float   # Абсолютный минимум
    max_value: float   # Абсолютный максимум
    
    def is_in_range(self, value: float) -> bool:
        return abs(value - self.target) <= self.tolerance
```

```
СИТУАЦИЯ: Риск растёт

T+0ms (Sensor):
  risk = 0.65 (выше нормы 0.3)
  → Sensor публикует: MetricUpdate("risk", 0.65)

T+10ms (Trigger):
  if risk > 0.6:
      → FIRE: "elevated_risk" trigger
      → Action: reduce_speed()

T+100ms (HomeoController):
  error = 0.65 - 0.3 = 0.35 (слишком высоко)
  → regulation_force = -gain * error = -0.5
  → continuously подавляет risky actions

T+1min (Hormone):
  cortisol_level += 0.3
  → risk_tolerance_multiplier = 1 - 0.3 * 0.5 = 0.85
  → ВСЕ решения получают penalty на рискованные опции

T+30min:
  cortisol_level = 0.3 * 0.5 = 0.15
  → penalty уменьшается

T+60min:
  cortisol_level ≈ 0
  → гормон больше не влияет
  → но homeocontroller всё ещё работает!

СИСТЕМЫ РАБОТАЮТ ПАРАЛЛЕЛЬНО И НЕЗАВИСИМО!
```

### 🏢 PwC Agent OS — Простым языком

#### Аналогия: Диспетчерская аэропорта

```
Представь себе большой аэропорт.

В аэропорту:
• Много авиакомпаний (American Airlines, Lufthansa, etc) = много AI агентов

Что делает диспетчерская:
```

#### Аналогия: Гормоны в теле человека

```
Ты знаешь что такое гормоны?

Это химические "курьеры" в теле:

• Адреналин: страх → сердце бьётся быстрее
• Кортизол: стресс → организм готовится к опасности  
• Мелатонин: темнота → хочется спать
• Инсулин: еда → сахар в крови снижается

Гормоны ДЕЙСТВУЮТ ДОЛГО:
• Выброс адреналина → эффект 10-30 минут
• Кортизол может влиять часами
• Мелатонин работает пока не выспишься

Это в отличие от НЕРВНЫХ ИМПУЛЬСОВ:
• Нервный импульс = мгновенный (миллисекунды)
• Гормон = медленный, долгий эффект

Digital Hormones = то же самое для AI агента!
```

#### Математика (простая версия):

```
ПРЕДСТАВЬ ведро с водой:

h(t+1) = h(t) + S(t) + R(t) + D(t) - K * h(t)
     │
     ├── h(t) = сколько воды в ведре сейчас
     ├── S(t) = добавили из крана (сенсоры)
     ├── R(t) = добавили из другого ведра (реакция)
     ├── D(t) = добавили от соседей (диффузия)
     └── K = дырка в ведре (распад)

ЕСЛИ нет новой воды и K=0.1:
• Минута 1: 1.0 ведра
• Минута 2: 0.9 ведра  
• Минута 3: 0.81 ведра
• ...
• Минута 10: 0.35 ведра
• Минута 20: 0.12 ведра

Это и есть РАСПАД гормона!
```

#### Реальный пример: Страх у робота

```
СИТУАЦИЯ: Робот чуть не упал с лестницы

1. СЕНСОР: "edge_detected", "unsteady_balance"
   → Выброс: cortisol_like_hormone += 0.8

2. ГОРМОН ВЛИЯЕТ:
   • Risk tolerance: 0.8 → 0.3 ("опасно!")
   • Decision speed: normal → fast ("надо быстрее!")
   • Curiosity: 0.6 → 0.2 ("не время исследовать!")
   • Memory formation: усиленная запись этого события

3. РОБОТ ДЕЙСТВУЕТ:
   • Отходит от края
   • Запоминает: "那里有边缘" (那里有边缘 = там есть край)
   • Больше не подходит так близко

4. РАСПАД:
   Через 30 минут cortisol падает
   Робот возвращается к нормальному поведению
   
ЧЕРЕЗ ЧАС:
   cortisol ≈ 0.05 (почти ноль)
   Риск-толерантность снова 0.8
   Но память об опасности ОСТАЛАСЬ!
```

### 🏠 Homeostasis — Простым языком

#### Аналогия: Термостат в доме

```
Ты знаешь как работает термостат?

Зимой на улице холодно.
Дома должно быть тепло.
Термостат говорит: "Включи отопление!"

Прошло время. Стало тепло.
Термостат говорит: "Хватит, выключи отопление!"

Это и есть ГОМЕОСТАЗ - поддержание нужной температуры.

Температура в доме = "метрика"
Желаемая температура (22°C) = "setpoint"
Термостат = "homeostatic controller"
```

#### Как это работает в теле человека:

```
┌─────────────────────────────────────────────────────────────┐
│  ГОМЕОСТАЗ В ТЕЛЕ                                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  МЕТРИКА           │ SETPOINT    │ ДЕЙСТВИЕ               │
│  ──────────────────────────────────────────────────────────  │
│  Температура тела  │ 36.6°C     │ Потеть / Дрожать      │
│  Уровень сахара    │ 5.5 ммоль/л│ Есть / Не есть        │
│  Кровяное давление │ 120/80     │ Расслабиться / etc    │
│  Уровень воды      │ ~60%       │ Пить / Мочегонное     │
└─────────────────────────────────────────────────────────────┘

КОГДА ВСЁ НОРМАЛЬНО:
Тело работает в штатном режиме

КОГДА ОТКЛОНЕНИЕ:
• Слишком жарко → потеем
• Слишком холодно → дрожим  
• Мало сахара → хотим есть
• Много сахара → инсулин

ЭТО ПРОИСХОДИТ АВТОМАТИЧЕСКИ!
Не нужно думать "щас я попотею".
Тело само регулирует.
```

#### Как это работает в AI агенте:

```
┌─────────────────────────────────────────────────────────────┐
│  ГОМЕОСТАЗ В НАШЕМ АГЕНТЕ                                 │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  МЕТРИКА           │ SETPOINT    │ ЗОНА ОК    │ ДЕЙСТВИЕ  │
│  ──────────────────────────────────────────────────────────  │
│  Risk (Q)          │ 0.3        │ 0.2-0.4   │ СТОП!     │
│  Quality (Ψ)       │ 0.8        │ 0.7-0.9   │ Улучшить  │
│  Reputation (Υ)    │ 0.7        │ 0.6-0.8   │ REPAIR    │
│  Curiosity (C)     │ 0.5        │ 0.3-0.7   │ Explore   │
│  Budget (B)        │ 0.5        │ 0.3-0.7   │ Allocate  │
└─────────────────────────────────────────────────────────────┘

ПРИМЕР: Risk вышел из зоны
┌─────────────────────────────────────────────────────────────┐
│  СЕЙЧАС: Q(Risk) = 0.75 (ВЫШЕ ЗОНЫ 0.2-0.4!)            │
│                                                             │
│  1. HomeostaticController видит: deviation = 0.75 - 0.3   │
│     deviation = +0.45 (выше нормы)                         │
│                                                             │
│  2. Генерирует drive: "снизь риск!"                        │
│                                                             │
│  3. Что происходит:                                        │
│     • Trigger: FIRE_RISK_REDUCTION                         │
│     • Hormone: produce("caution", 0.5)                     │
│     • Action: выбрать более безопасный путь                │
│                                                             │
│  4. ЧЕРЕЗ ВРЕМЯ:                                          │
│     Q(Risk) = 0.35 (вернулся в зону!)                     │
│     Drive = 0 (ничего делать не нужно)                     │
└─────────────────────────────────────────────────────────────┘
```

#### Контроллер (простая версия):

```
Термостат с П-регулятором:

drive = -gain * (current_value - target_value)

Если current = 25°C, target = 22°C:
  drive = -1 * (25 - 22) = -3 (выключить отопление!)

Если current = 19°C, target = 22°C:
  drive = -1 * (19 - 22) = +3 (включить отопление!)

Если current = 21.5°C, target = 22°C:
  drive = -1 * (21.5 - 22) = +0.5 (немного включить)
  
Если current = 22°C:
  drive = 0 (идеально!)
```

```

╠═══════════════════════════════════════════════════════════════════╣
║                                                                   ║

║                                                                   ║
║  НАША ТЕКУЩАЯ ПРОБЛЕМА:                                       ║
║  Сейчас мы СЛЕДИМ за метриками (через триггеры),              ║
║  но не АВТОМАТИЧЕСКИ ИХ РЕГУЛИРУЕМ.                          ║
║                                                                   ║
║  КАК УКРАСТЬ:                                                  ║
║  ┌─────────────────────────────────────────────────────────┐     ║

║  │              "risk": Setpoint(target=0.3, tol=0.1),    │     ║

║  │          if metric == "risk" and current > sp.max:     │     ║

║  │          elif metric == "quality" and current < sp.min│     ║
║  │              return Action("improve_quality")          │     ║
║  └─────────────────────────────────────────────────────────┘     ║
║                                                                   ║
║  ПОЧЕМУ УКРАСТЬ:                                               ║
║  • Агент САМ поддерживает себя в порядке                      ║
║  • Не нужно ждать внешнего триггера                           ║
║  • Как термостат - работает всегда                             ║
║  • Можно настраивать setpoints под разные задачи              ║
╚═══════════════════════════════════════════════════════════════════╝
```

> **Статус:** ⏳ В РАЗРАБОТКЕ

> **Назначение:** Формализация "ниточек", которые дёргают агента

### Метафора: Марионетка и кукловод

```
ОРКЕСТРАТОР = Марионетка (исполнитель)
ТРИГГЕРЫ = Нервные связи (сигналы к действию)

Мы прокладываем нервы от метрик к решениям:
• Метрика → Триггер → Импульс → Цепочка действий
```

**Существующие метрики (нервы уже есть):**
```
Φ(Profit)        → выход: profit_score ∈ [-1, 1]
Υ(Reputation)    → выход: reputation_score ∈ [-1, 1]
Ω(Evolution)     → выход: evolution_score ∈ [-1, 1]
Q(Risk)          → выход: risk_score ∈ [0, 1]
Ψ(Quality)       → выход: quality_score ∈ [0, 1]
Γ(Compliance)    → выход: {PASS, FAIL}
```

**Свободные концы (не подключены):**
```
❌ Что делать когда profit_score < -0.5?
❌ Что делать когда risk_score > 0.7?
❌ Что делать когда reputation_score падает?
❌ Что делать когда curiosity_score > 0.6?
```

---

### Категории триггеров

#### 1. ПОРОГОВЫЕ (Threshold-based)
Когда метрика пересекает заданное значение:

```
• risk_score > 0.7       → RISK_WARNING
• budget_ratio < 0.1     → LOW_BUDGET
• reputation_score < 0.3 → REPUTATION_DROP
• curiosity_score > 0.6 → CURIOSITY_FIRE
```

#### 2. ДЕЛЬТА (Delta-based)
Когда метрика резко меняется:

```
• profit_delta > +0.3    → PROFIT_SPIKE (хорошо!)
• profit_delta < -0.2    → PROFIT_DIVE (плохо!)
• reputation_delta < -0.1 → REPUTATION_EROSION
• risk_delta > +0.2      → RISK_ACCELERATION
```

#### 3. СКОРОСТЬ (Rate-based)
Как быстро меняется метрика:

```
• risk_acceleration > threshold → DANGER_MODE
• opportunity_window closing    → URGENT_ACTION
• deadline_approach_rate      → TIME_PRESSURE
```

#### 4. ПАТТЕРН (Pattern-based)
Комбинации метрик:

```
• low_profit AND high_risk  → REFUSE_PATTERN
• high_opportunity AND low_budget → CHALLENGE_PATTERN
• low_quality AND high_deadline → STRESS_PATTERN
• rising_reputation AND high_quality → GROWTH_PATTERN
```

#### 5. РАСПИСАНИЕ (Scheduled)
Регулярные проверки по таймеру:

```
• CRON: 0 8 * * *    → DAILY_REFRESH (8 AM)
• CRON: 0 * * * *    → HOURLY_HEALTH_CHECK
• CRON: 0 0 * * 1    → WEEKLY_STRATEGIC_REVIEW
• CRON: */15 * * * * → QUARTERLY_METRICS
```

### Формализация триггера

```python
@dataclass
class Trigger:
    """
    Триггер = нервная связь
    
    НИТОЧКИ, которые дёргают марионетку:
    • source_metric — откуда сигнал
    • condition — когда срабатывает
    • action — что делать
    """
    
    # Идентификация
    name: str                    # RISK_WARNING, LOW_BUDGET, etc
    description: str              # Человеческое описание
    
    # Источник
    source_metric: str            # risk_score, budget_ratio, etc
    metric_path: str             # путь в AgentState: "metrics.risk.score"
    
    # Условие срабатывания
    condition: ConditionType      # gt, lt, delta_gt, delta_lt, rate_gt, pattern
    threshold: float             # Порог
    threshold_high: float         # Для гистерезиса (верхняя граница)
    threshold_low: float         # Для гистерезиса (нижняя граница)
    
    # Приоритет и управление
    priority: int                # 1 = highest (danger), 5 = lowest
    enabled: bool                # Включён/выключен
    cooldown: timedelta          # Минимум между срабатываниями
    
    # Связь с существующими функциями
    related_functions: List[str]  # Φ, Υ, Ω, Q, Ψ, Γ
    
    # Действие при срабатывании
    action_type: ActionType      # WARNING, URGENT, EXPLORE, OPPORTUNITY, etc
    impulse_type: ImpulseType    # Что генерировать: CURIOUS, WARNING, etc
    
    # Что делать
    recommended_chain: str        # Какую цепочку запустить
    
    # Настраиваемые параметры (для человека)
    tunable: bool                # Можно ли менять пороги
    user_override: Optional[dict] # Ручные настройки


@dataclass  
class ConditionType:
    """Типы условий срабатывания"""
    THRESHOLD_GT = "gt"          # Больше чем
    THRESHOLD_LT = "lt"          # Меньше чем
    THRESHOLD_BETWEEN = "between" # Между (с гистерезисом)
    DELTA_GT = "delta_gt"        # Изменение больше чем
    DELTA_LT = "delta_lt"        # Изменение меньше чем
    RATE_GT = "rate_gt"          # Скорость больше чем
    PATTERN_MATCH = "pattern"    # Паттерн метрик совпал
    EQUAL = "eq"                 # Равно
    CRON = "cron"                # По расписанию


@dataclass
class ActionType:
    """Типы действий при срабатывании"""
    # Критические
    LOCKDOWN = "lockdown"        # Всё остановить
    VETO = "veto"                # VETO mode
    WARNING = "warning"          # Предупреждение
    
    # Реактивные
    REPAIR = "repair"            # Починить проблему
    ESCALATE = "escalate"        # Эскалировать человеку
    RETRY = "retry"              # Повторить попытку
    
    # Проактивные  
    EXPLORE = "explore"          # Исследовать
    OPPORTUNITY = "opportunity"  # Действовать по возможности
    MONITOR = "monitor"          # Усилить мониторинг
    
    # Информационные
    LOG = "log"                  # Просто записать
    METRICS_UPDATE = "update"    # Обновить метрики
    HEALTH_CHECK = "check"       # Health check
```

```python
class TriggerOptimizer:
    """
    Оптимизация триггеров на основе обратной связи
    
    Пользователь говорит: "этот триггер сработал неправильно"
    Система корректирует пороги
    """
    
    def on_trigger_feedback(
        self,
        trigger_name: str,
        was_useful: bool,
        context: dict
    ):
        """
        Обработка обратной связи
        """
        if not was_useful:
            if context.get("too_sensitive"):
                # Было слишком чувствительно
                self.increase_threshold(trigger_name)
                self.extend_cooldown(trigger_name)
            elif context.get("too_late"):
                # Сработал слишком поздно
                self.decrease_threshold(trigger_name)
        else:
            # Запоминаем что было хорошо
            self.record_successful_trigger(trigger_name)
    
    def suggest_optimizations(self) -> List[OptimizationSuggestion]:
        """
        Предлагает оптимизации based on statistics
        """
        suggestions = []
        
        for trigger in self.triggers:
            # Статистика
            firing_rate = self.get_firing_rate(trigger.name)
            false_positive_rate = self.get_false_positive_rate(trigger.name)
            avg_response_time = self.get_avg_response_time(trigger.name)
            
            if firing_rate > 20:  # Слишком часто
                suggestions.append(
                    OptimizationSuggestion(
                        trigger=trigger.name,
                        action="increase_cooldown",
                        reason=f"Firing {firing_rate}x per day",
                        estimated_impact="reduce_noise"
                    )
                )
            
            if false_positive_rate > 0.5:  # >50% ложных
                suggestions.append(
                    OptimizationSuggestion(
                        trigger=trigger.name,
                        action="adjust_threshold",
                        reason=f"{false_positive_rate*100:.0f}% false positives",
                        estimated_impact="improve_accuracy"
                    )
                )
        
        return suggestions
```

### 1. Концепция

**Mission** определяет **ИДЕНТИЧНОСТЬ** агента — кто я такой, что для меня важно, чем я НЕ буду жертвовать.

Mission — это НЕ optimization target. Это **POLICY CALIBRATION**:
- Не "максимизировать X"
- А "калибровать веса и пороги так, чтобы это соответствовало моей миссии"

**Аналогия:** Человек-профессионал
- Его "миссия" — быть хорошим врачом/юристом/инженером
- Это определяет его **приоритеты** (важнее спасти жизнь, чем заработать)
- Это определяет его **границы** (я не буду делать аборты, если это противоречит моим убеждениям)
- Это определяет его **стандарты** (минимальное качество работы)

```python
    """
    MISSION CALIBRATION
    
    Это НЕ optimization. Это policy decision.
    Mission "решает" что ему важно на основе своей identity и principles.
    """
    
    def calibrate(
        self,
        mission: MissionProfile,
        agent_state: AgentState,
        context: MissionContext
    ) -> PolicyParams:
        """
        Калибрует PolicyParams на основе миссии.
        
        INPUT:
        - mission: кто я такой (Identity + Principles + Type)
        - agent_state: моё текущее состояние (C_spent, Φ_hist, etc.)
        - context: внешний контекст (P_market, конкуренты, etc.)
        
        OUTPUT:
        - PolicyParams: веса, пороги, правила для всех функций
        """
        
        # === ШАГ 1: Базовые веса из типа миссии ===
        base_weights = self.get_base_weights(mission.mission_type)
        
        # === Шаг 2: Модификация на основе состояния ===
        # Если агент в хорошем состоянии — может "позволить себе" другие приоритеты
        state_modifier = self.compute_state_modifier(agent_state, mission)

        # === Шаг 3: Принципы → Γ_rules ===
        gamma_rules = self.principles_to_gamma_rules(mission.principles)
        
        # === Шаг 4: Определяем пороги ===

    ) -> StateModifier:
        """
        Модифицирует веса на основе текущего состояния агента.
        
        Examples:
        - Если C_spent > B_client * 0.9 → увеличить λ_profit
        - Если Φ_hist < 0 (убыток) → увеличить λ_profit, снизить λ_evolution
        - Если Υ_rating < 3.0 → увеличить λ_reputation
        """
        modifiers = {}
        
        # === Финансовое состояние ===
        if state.C_spent > state.B_total * 0.9:
            # Критический бюджет
            modifiers["lambda_profit"] = 1.3
            modifiers["lambda_evolution"] = 0.7
        
        if state.Φ_historical < 0:
            # Убыточный период
            modifiers["lambda_profit"] = modifiers.get("lambda_profit", 1.0) * 1.2
        
        # === Репутационное состояние ===
        if state.Υ_current < 3.0:
            # Низкий рейтинг
            modifiers["lambda_reputation"] = 1.5
        
        if state.N_tasks_failed > state.N_tasks_done * 0.3:
            # Высокий процент провалов
            modifiers["lambda_quality"] = 1.3
        
        # === Эволюционное состояние ===
        if state.K_knowledge < state.K_max * 0.3:
            # Мало знаний — нужно учиться
            modifiers["lambda_evolution"] = 1.4
        
        return StateModifier(**modifiers)
    
    def apply_modifier(
        self, 
        base: Weights, 
        modifier: StateModifier
    ) -> Weights:
        """Применяет state modifier к базовым весам."""
        result = base.copy()
        
        for key, value in modifier.__dict__.items():
            if hasattr(result, key):
                current = getattr(result, key)
                setattr(result, key, current * value)
        
        # Нормализация
        total = sum(result.__dict__.values())
        for key in result.__dict__:
            setattr(result, key, getattr(result, key) / total)
        
        return result
    
    def principles_to_gamma_rules(
        self, 
        principles: List[Principle]
    ) -> GammaRules:
        """
        Превращает принципы миссии в Γ_rules.
        
        Hard principles → Γ_rules (VETO)
        Soft principles → penalty в функции полезности
        """
        hard_rules = []
        soft_rules = []
        
        for p in principles:
            rule = GammaRule(
                name=p.name,
                description=p.description,
                priority=p.priority,
            )
            
            if p.is_hard:
                hard_rules.append(rule)
            else:
                soft_rules.append(rule)
        
        return GammaRules(
            hard=hard_rules,
            soft=soft_rules,
        )
    
    def compute_thresholds(
        self, 
        mission: MissionProfile, 
        state: AgentState
    ) -> Thresholds:
        """
        Определяет пороги q_min, ψ_max, c_max.
        
        Зависит от:
        - Типа миссии (premium требует высокого quality)
        - Личности (perfectionist требует высокого quality)
        - Состояния (если в убытке — допускаем больший риск)
        """
        
        # === q_min — минимальное качество ===
        quality_boost = self.PERSONALITY_MODIFIERS.get(
            mission.personality.quality_attitude, {}
        ).get("quality_boost", 1.0)
        
        # Premium миссия требует высокого качества
        if mission.mission_type == MissionType.PREMIUM:
            base_quality = 0.9
        elif mission.mission_type == MissionType.SURVIVAL:
            base_quality = 0.5  # Выживание — качество вторично
        else:
            base_quality = 0.7
        
        q_min = base_quality * quality_boost
        
        # === ψ_max — максимальный риск ===
        risk_tolerance = self.PERSONALITY_MODIFIERS.get(
            mission.personality.risk_profile, {}
        ).get("risk_tolerance", 0.5)
        
        # Модификация на основе состояния
        if state.Φ_historical < 0:
            # В убытке — готовы рисковать больше
            risk_tolerance *= 1.2
        
        ψ_max = risk_tolerance * state.B_total * 0.5
        
        # === c_max — максимальная стоимость ===
        money_boost = self.PERSONALITY_MODIFIERS.get(
            mission.personality.money_attitude, {}
        ).get("cost_penalty", 1.0)
        
        c_max = state.C_remaining * (2.0 / money_boost)
        
        return Thresholds(
            q_min=q_min,
            psi_max=ψ_max,
            c_max=c_max,
        )
```

```python
class MissionManager:
    """
    Управляет изменениями Mission.
    
    Mission может меняться:
    1. Manual: явно через user request или explicit reconfiguration
    2. Automatic: через state-based triggers (редко, осторожно)
    3. Gradual: через B(·) Bayesian optimizer (калибровка весов)
    """
    
    # === MANUAL CHANGES ===
    def update_mission(self, new_mission: MissionProfile, reason: str):
        """
        Явное изменение миссии пользователем.
        Требует подтверждения и создаёт checkpoint.
        """
        # Создать checkpoint текущей миссии
        self.create_checkpoint(self.current_mission, reason)
        
        # Применить новую миссию
        self.current_mission = new_mission
        
        # Recalibrate все параметры
        self.recalibrate()
        
        # Audit log
        self.log_change(reason, new_mission)
    
    # === AUTOMATIC CHANGES (редко) ===
    def auto_transition(self, trigger: MissionTrigger) -> bool:
        """
        Автоматический переход между типами миссий.
        
        Примеры триггеров:
        - C_spent > B_total * 0.95 → SURVIVAL
        - Φ_historical > B_total * 0.5 → MAXIMIZE
        - Υ_rating < 2.5 → MAINTENANCE
        """
        thresholds = {
            "survival_trigger": self.agent_state.C_spent > self.agent_state.B_total * 0.95,
            "prosperity_trigger": self.agent_state.Φ_historical > self.agent_state.B_total * 0.5,
            "reputation_critical": self.agent_state.Υ_current < 2.5,
        }
        
        if thresholds.get(trigger):
            return self.request_manual_approval(trigger)
        return False
    
    # === BAYESIAN CALIBRATION (часто) ===
    def calibrate_weights(self, observations: List[Outcome]):
        """
        B(·) калибрует веса на основе наблюдений.
        Это НЕ меняет Mission, это fine-tuning.
        """
        # Bayesian update весов на основе feedback
        new_weights = self.bayesian_update(
            prior=self.current_mission_weights,
            observations=observations
        )
        
        # Ограничить изменения — не более ±10% от базовых
        clamped_weights = self.clamp_weights(
            new_weights,
            base=self.current_mission_weights,
            max_delta=0.1
        )
        
        return clamped_weights
```

```python
class MissionDriftDetector:
    """
    Обнаружение mission drift через формальную верификацию.
    """
    
    def __init__(self, mission: MissionProfile):
        # Mission-Time Temporal Logic (MTL) specifications
        self.specs = self.mission_to_mtl(mission)
        
        # Runtime monitor (R2U2-style)
        self.monitor = RuntimeMonitor(self.specs)
    
    def check_drift(self, action_sequence: List[Action]) -> DriftReport:
        """
        Проверяет последовательность действий на соответствие миссии.
        """
        violations = self.monitor.verify(action_sequence)
        
        if violations:
            return DriftReport(
                severity=self.compute_severity(violations),
                violations=violations,
                recommendation=self.get_recommendation(violations)
            )
        return DriftReport(severity="OK", violations=[], recommendation=None)
    
    def mission_to_mtl(self, mission: MissionProfile) -> List[MTLSpec]:
        """
        Конвертирует Mission Profile в Mission-Time Temporal Logic specs.
        
        Примеры:
        - G(quality >= q_min) — всегда quality >= q_min
        - F(complete) — eventually complete task
        - !violate_critical_principles — никогда не нарушать critical principles
        """
        specs = []
        
        # Quality constraint
        specs.append(f"G(quality >= {mission.thresholds.q_min})")
        
        # Risk constraint  
        specs.append(f"G(risk <= {mission.thresholds.psi_max})")
        
        # Critical principles
        for p in mission.principles:
            if p.priority == "critical":
                specs.append(f"G(!{p.name})")  # Never violate
        
        return specs
```

```python
class InverseRewardDesigner:
    """
    IRD: трактуем proxy reward как evidence о настоящей награде.
    
    Основная идея:
    - Дизайнер дал нам proxy reward
    - Это reward из proxy environment (не настоящего)
    - Нужно восстановить uncertainty о настоящей reward
    - Plan risk-averse с учётом этой uncertainty
    """
    
    def plan_with_ird(
        self,
        proxy_reward: RewardFunction,
        training_env: Environment,
        actual_env: Environment
    ) -> Plan:
        """
        Планирование с учётом reward uncertainty.
        """
        # Шаг 1: Инfer reward posterior
        # P(R_true | R_proxy, env_proxy) 
        reward_posterior = self.infer_reward_posterior(
            proxy_reward,
            training_env
        )
        
        # Шаг 2: Risk-averse planning
        # Вместо max R_proxy, ищем план который хорош
        # для всех R в posterior с высокой вероятностью
        return self.robust_optimize(
            reward_posterior=reward_posterior,
            planning_algorithm=self.mcts,
            risk_measure="CVaR"
        )
```

```python
        graph_metrics = self.compute_graph_metrics(task)
        
        # b^d search bound (branching factor × depth)
        search_bound = graph_metrics.avg_branching ** graph_metrics.depth
        
        # Critical path analysis
        critical_path = self.find_critical_path(task)
        
        # === RISK PROXIES ===
        # VaR / CVaR для risk assessment
        var_95 = self.compute_var(task, confidence=0.95)
        cvar_95 = self.compute_cvar(task, confidence=0.95)
        
        # === SAMPLING PASS (lightweight) ===
        success_prob, expected_cost = self.monte_carlo_estimate(
            task,
            n_rollouts=50  # Budgeted
        )
        
        return ComplexityReport(
            search_bound=search_bound,
            critical_path_length=critical_path.length,
            n_critical_tasks=critical_path.n_tasks,
            var_95=var_95,
            cvar_95=cvar_95,
            success_probability=success_prob,
            expected_cost=expected_cost,
            recommendation=self.get_recommendation(search_bound, success_prob)
        )
    
    def compute_graph_metrics(self, task: Task) -> GraphMetrics:
        """
        Вычисляет метрики task graph.
        """
        # Precedence constraints density
        density = len(task.dependencies) / (task.n_tasks * (task.n_tasks - 1))
        
        # Parallelizability (how much can be done in parallel)
        parallelizability = self.compute_critical_path_ratio(task)
        
        # Fan-out (max children per task)
        fan_out = max(t.n_subtasks for t in task.subtasks)
        
        return GraphMetrics(
            n_tasks=task.n_tasks,
            depth=task.depth,
            avg_branching=task.avg_branching,
            density=density,
            parallelizability=parallelizability,
            fan_out=fan_out,
        )
```

```python
class NormativeLayer:
    """
    Иерархия норм в MAS.
    
    Categories:
    - Regulative: регулируют процесс (когда, как)
    - Constitutive: конституируют (создают институты)
    
    Strengths:
    - Hard (must) > Soft (should) > Preference
    """
    
    NORM_HIERARCHY = {
        "prohibition": 1,   # Запрещено (Γ_rules)
        "obligation": 2,    # Обязательно (critical principles)
        "permission": 3,    # Разрешено (high principles)
        "facultation": 4,  # Можно (medium/low principles)
    }
    
    def evaluate_action(self, action: Action, context: Context) -> NormResult:
        """
        Оценивает действие против иерархии норм.
        """
        for norm in self.get_applicable_norms(action):
            strength = self.NORM_HIERARCHY[norm.type]
            
            if norm.type == "prohibition":
                if norm.is_violated(action, context):
                    return NormResult(
                        status="REJECT",
                        reason=f"Prohibition violated: {norm.name}",
                        norm=norm
                    )
            
            elif norm.type == "obligation":
                if not norm.is_satisfied(action, context):
                    penalty = self.compute_penalty(norm, strength)
                    # Soft rejection, но с penalty
        
        return NormResult(status="APPROVE", penalties=[])
```

#### 5.1 Separation of Hard vs Soft

**Ключевая идея:** Mission определяет *soft* preferences, Compliance определяет *hard* constraints.

```
Priority: Γ (VETO) > M (Policy) > остальное
```

```python
class DecisionFlow:
    """
    Flow принятия решения с иерархией.
    """
    
    def evaluate(self, task: Task) -> Decision:
        
        # === STEP 1: Γ — HARD VETO ===
        gamma_result = self.compliance.evaluate(task)
        if gamma_result.status == "FAIL":
            return Decision(
                action="REJECT",
                reason=f"Γ VETO: {gamma_result.reason}",
                blocker="compliance"
            )
        
        # === STEP 2: Mission calibration ===
        policy_params = self.mission.calibrate(
            self.current_mission,
            self.agent_state,
            self.context
        )
        
        # === STEP 3: Strategic functions ===
        phi = self.profit.evaluate(task, policy_params)
        upsilon = self.reputation.evaluate(task, policy_params)
        omega = self.evolution.evaluate(task, policy_params)
        
        # === STEP 4: Tactical functions ===
        quality = self.quality.evaluate(task, policy_params)
        risk = self.risk.evaluate(task, policy_params)
        
        # === STEP 5: Compose decision ===
        utility = (
            policy_params.weights.lambda_profit * phi +
            policy_params.weights.lambda_reputation * upsilon +
            policy_params.weights.lambda_evolution * omega
        )
        
        if quality < policy_params.thresholds.q_min:
            utility *= 0.5  # Penalty за низкое качество
        
        if risk > policy_params.thresholds.psi_max:
            return Decision(
                action="REJECT",
                reason=f"ψ MAX exceeded: {risk} > {policy_params.thresholds.psi_max}",
                blocker="risk"
            )
        
        return Decision(
            action="EXECUTE" if utility > self.threshold else "CLARIFY",
            utility=utility,
            details={...}
        )
```
